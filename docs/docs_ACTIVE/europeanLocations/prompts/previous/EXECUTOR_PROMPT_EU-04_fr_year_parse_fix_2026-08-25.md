## 2. The defect, stated precisely

`openubem/acquisition/bdtopo_fetcher.py:94`

```python
out["year_built"] = pd.to_datetime(raw["date_d_apparition"], format="mixed", errors="coerce").dt.year.astype("Int64")
```

BD TOPO returns values shaped `1998-01-01Z`, `1820-01-01Z`, `1580-01-01Z` — a date with
a bare zone suffix and no time part. On pandas 3.0.3 this reproduces exactly:

```python
pd.to_datetime(pd.Series(["1998-01-01Z", "1820-01-01Z", "1580-01-01Z"]), format="mixed", errors="coerce")
# -> [NaT, NaT, NaT]
```

Three compounding causes: the bare `Z` with no time part; values before 1677 falling
outside `datetime64[ns]`; and `errors="coerce"` silently converting both into `NaT`.

**Measured consequence.** An authorized live probe of the pinned Lyon bbox
`(45.774784, 45.768891, 4.837450, 4.823612)` returned **1,663** raw features, of which
**1,115** carry `date_d_apparition` and **1,176** carry `nombre_de_logements`. The
retained manifest `openubem/outputs/eu02/FR-LYO-HAUTCOEURPENTES/02_residential_manifest.gpkg`
holds **530** residential rows with **0** non-null `year_built`, every one stamped
`provenance_year_built='IGN_BDTOPO_MISSING'` / `data_quality_flag='no_year'`.

**Why the suite did not catch it.** `tests/test_eu02_fetchers.py:20,47` feeds the fixture
`"1980-01-01"` — no zone suffix, post-1677 — which parses fine. The fixture does not
resemble the source.

## 4. Tasks

### T01 — Parse the construction year from the leading date, never through a datetime round-trip

**What.** Replace the `year_built` expression at `openubem/acquisition/bdtopo_fetcher.py:94`
so it extracts the leading four-digit year from `date_d_apparition` as an integer,
independently of any timestamp representation.

**Why.** The year is a plain calendar year in the source. Routing it through
`datetime64[ns]` imposes a 1677–2262 range that the French stock genuinely violates
(1580 is a real observed value here), and the zone suffix defeats `format="mixed"`.
There is no reason to build a timestamp only to take `.dt.year` from it.

**How.**
- Extract the leading `YYYY` with a strict anchored pattern (a four-digit run at the
  start of the string), convert to nullable `Int64`, and leave every non-matching or
  null value as `pd.NA`.
- Apply a plausibility floor and ceiling and **exclude** — do not clamp — anything
  outside it: reject `year < 1000`, and reject any year greater than the current year.
  A rejected value becomes `pd.NA`, so `finalize_footprints` stamps it
  `IGN_BDTOPO_MISSING` exactly as it does a genuinely absent value.
- Keep the output dtype `Int64` — `openubem/semantic/european_archetype_mapping.py:62`
  requires an integral year and `tests/test_eu02_fetchers.py:25` asserts the dtype.
- Do **not** touch `date_de_confirmation`, and do not add it as a fallback: it records
  a confirmation event, not construction.

**How to test.** Run the new expression against
`["1998-01-01Z", "1820-01-01Z", "1580-01-01Z", "2010-06-15Z", None, "", "not-a-date"]`
and confirm `[1998, 1820, 1580, 2010, NA, NA, NA]`. Paste the output in your report.
