### N13 — Is T07 the only completion record whose code was never committed? (OPEN-36)

**What to do.** Sweep every progress-log entry in the project that (a) is marked completed and (b)
names a code artifact, and check whether that artifact exists at HEAD and in git history. Deliver a
per-entry verdict table.

**Why.** OPEN-36's stated first measurement, verbatim: *"**Whether T07 is unique.** Every arc's
progress log makes claims of this shape. The measurement is mechanical and needs no CPU… **Nobody has
ever done this, and until it is done the reliability of every closure record in the project is
unmeasured.**"* This register's entire method rests on reading completion records.

**How.**
- **Build the population first, and state its size before judging any entry.** Progress-log entries
  follow the project's template — `#### TXX — <title> — completed YYYY-MM-DD` — across `docs_DONE/`,
  `docs_main/`, `docs_ACTIVE/` and `docs_INVESTIGATE/`. **Report how many entries you found and how
  many name a checkable code artifact.** Those two numbers are a result in themselves.
- **A "checkable code artifact" is a named symbol or file under `openubem/`, `scripts/` or `tests/`.**
  Prose like *"wired the router"* is **not** checkable — count those separately as **UNCHECKABLE**,
  which is its own finding about the template.
- **Four verdicts, and no others:** **PRESENT** (exists at HEAD), **MOVED** (absent at HEAD but a
  commit contains it — quote the commit), **NEVER-COMMITTED** (`git log --all -S` finds nothing on any
  branch), **UNCHECKABLE**.
- **Method validation, required.** Run **T07** through your procedure blind and confirm it returns
  **NEVER-COMMITTED**. If it does not, your method is wrong: **STOP and report.** T07 is the known
  positive; a sweep that cannot find it cannot be trusted on anything else.
- **Scope honestly and say so.** If the full population is too large, sweep a **stated, principled**
  subset — e.g. every entry in the arcs the adopted baseline depends on — and **name what you did not
  cover.** §2 rule: no silent caps.
- **Do not fix, and do not judge the executor who wrote an entry.** Record the state of the record.

**How to test.** (a) Verdict counts sum to the checkable-artifact count; print both plus the total
population. (b) The T07 control returns NEVER-COMMITTED — stated pass/fail. (c) Every
NEVER-COMMITTED verdict carries the exact `git log --all -S` command a reader can re-run.

**Artifacts.** `extra/MEASUREMENT_open-36_completion-record-sweep.md` +

### N15 — Did the fleet's Stage-1 files ever consume the height backfill? (OPEN-12 / OPEN-14)

**What to do.** Determine whether the pipeline path that produced the fleet's `01_buildings.gpkg` would
have consumed an Overture slice at all. Answer **yes / no / cannot be determined from files on disk.**

**Why.** §5.4: the four cells with no tracked slice are exactly the four worst for missing height, found
by two executors independently. **The register records this as an observation and explicitly refuses to
claim it.** This is the one step that decides whether OPEN-12 is a data-coverage problem (needing
better sources) or **is OPEN-14 wearing a different name** (needing a committed artifact). **Those have
completely different remedies, which is why guessing is not acceptable.**

**How.**
- **Trace the acquisition path**, not the fusion module in isolation: what writes `01_buildings.gpkg`,
  and under what configuration would `fuse()` contribute `height_m`? `config.py:141`'s empty
  `FUSION_SOURCES_BY_TARGET` is the load-bearing default — **establish whether any script overrides
  it**, and if one does, name it.
- **Then check the artifact's own history.** `git log --follow` on one affected cell's
  `01_buildings.gpkg`: when was it written, by which commit, and **was any Overture slice tracked in
  the tree at that moment?** A slice committed *after* the file was written cannot have been consumed
  by it — **and that alone may settle the question.**
- **Check the healthy cells too, and this is the discriminating step.** `nyc_centre` **does** have a
  tracked slice and **does** have heights for 84% of its buildings. **If the slice explains the
  healthy cells and its absence explains the sick ones, the convergence is a claim.** If `nyc_centre`'s
  heights came from raw OSM tags instead, **the convergence is a coincidence and must be reported as
  one.**
- **Report the direction honestly, whichever way it falls.** "Cannot be determined from files on disk"
  is an acceptable and useful result — **name what would settle it** and stop. Do not run the
  acquisition pipeline to find out; that is CPU and network, and it is forbidden here.

**How to test.** (a) A yes/no/undetermined verdict in one sentence at the top of the report. (b) The
`nyc_centre` discriminating check is reported explicitly, whichever way it falls. (c) Every claim
about what a file consumed carries a commit hash and a date, so a reader can check the ordering.

**Artifacts.** `extra/MEASUREMENT_open-12-14_backfill-consumption.md`.
