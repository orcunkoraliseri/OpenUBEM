## Verdict, up front

**Outcome 2 — the built prototype does NOT match the recorded archetype.** For all three OPEN-07
buildings, `05_results.gpkg` records `archetype_id = SmallOffice`, but the **T20 `layout_assign`
harvest's own surviving `eplusout.sql`** — the actual EnergyPlus run output for that exact building, that
exact generation — proves the IDF that was built and simulated used the **`SmallHotel`** baseline
prototype (`ASHRAE901_HotelSmall_STD2022_Buffalo.idf`), not the `SmallOffice` one
(`ASHRAE901_OfficeSmall_STD2022_Buffalo.idf`). This is **not silent** — the decisive artifact survives
locally for all three buildings and was read directly. The zone name **does** come from the archetype
(via a deterministic 1:1 lookup table); it is the `05_results.gpkg` label that is wrong about what ran.

This widens OPEN-06 from a labelling defect into a **provenance defect**: at least for these three
buildings, `archetype_id` in `05_results.gpkg` does not describe the T20-generation simulation it is
attached to. Per plan §7 CP-N3, this is flagged as a finding for the user, not deferred to the end of the
queue.

## 1. The prototype that owns `LAUNDRYROOMFLR1`, named with `path:line`

Repo-wide search for `LAUNDRYROOM` (case-insensitive) inside `openubem/` returned **zero matches** — the
zone name is not generated by any OpenUBEM code path; it is inherited verbatim from a DOE/ASHRAE
reference prototype IDF used as a baseline template.

The exact zone object is defined at:


That file's git state: `git log -1` → commit `e063865` (2026-06-30 19:07:12), unchanged since (working

**Which archetype owns that prototype file?** `openubem/geometry/layout_assigner.py:31`:

```python
"SmallHotel": "ASHRAE901_HotelSmall_STD2022_Buffalo.idf",
```

`ARCHETYPE_IDF_MAP` (lines 23-61) is a **deterministic, 1:1** mapping from OpenUBEM canonical
`archetype_id` to a baseline IDF filename — `git blame` on lines 23-40 shows the whole map, including
this exact `SmallHotel` line, was introduced in a single commit, `3a925f9` (2026-07-25 17:26:14), and
`layout_assigner.py`'s only later touch (`69373f9`, 2026-07-27) did not change these lines (verified by
`git show 69373f9 -- openubem/geometry/layout_assigner.py`, which only adds unrelated boiler-capacity
logic further down the file). So the map that would have been active at the T20 run (files below, mtimes
2026-07-26) already held this exact `SmallHotel → ASHRAE901_HotelSmall_STD2022_Buffalo.idf` entry.

**Prototype `ASHRAE901_HotelSmall_STD2022_Buffalo.idf` belongs to archetype `SmallHotel`.**

For comparison, `SmallOffice` maps to `ASHRAE901_OfficeSmall_STD2022_Buffalo.idf`
(`layout_assigner.py:36`). That file's zones (`Core_ZN`, `Perimeter_ZN_1..4`, `Attic`) contain **no**
`Laundry` zone and use an entirely different naming convention (no room-type names at all) — confirmed by
direct read, zero matches for `Laundry` anywhere in that file.

**Call chain from the T20 fleet entry point to this lookup** (one hop per line, all read at HEAD):

1. `scripts/cluster/t20_layout_assign_full_sweep.py` — `ALL_MODES = ["layout_assign"]` (line 80); calls
   `run_step3(..., resolution_mode=mode, ...)` (line 193) with `mode = "layout_assign"`.
2. `openubem/idf/builder.py:201` — `baseline_idf_path = _layout_assign_baseline_path(resolution_mode,
   row["archetype_id"])`.
3. `openubem/idf/builder.py:78` (inside `_layout_assign_baseline_path`) — `baseline_path =
   reg.get_baseline_idf(archetype_id)`.
4. `openubem/geometry/layout_assigner.py:121` (inside `LayoutAssigner.get_baseline_idf`) — `filename =
   ARCHETYPE_IDF_MAP.get(archetype_id)`.
5. `openubem/geometry/layout_assigner.py:31` — the map entry itself, `"SmallHotel" →
   "ASHRAE901_HotelSmall_STD2022_Buffalo.idf"`.

The `archetype_id` fed into this chain is `row["archetype_id"]` — i.e., whatever archetype the row
carried **at build time**, which per this chain is also the value that determines which zones exist in
the simulated model. It is a single deterministic lookup: no alternate path, no fallback that could
substitute a different template for the same `archetype_id` string.

**Conclusion: the IDF actually built and simulated for all three OPEN-07 buildings, at T20, was the
