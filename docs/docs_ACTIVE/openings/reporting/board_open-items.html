What this board does not say

The adopted fleet figure is 153.8231 kWh/m², pooled over 8,153 buildings, and nothing here restates it. Two items on this board sit underneath it. OPEN-56's volume stub is worth roughly +1.0 kWh/m² and is not included. OPEN-61 was sized on 2026-08-20 and is the larger of the two by an order of magnitude: 60 of 60 re-simulated production buildings carry the dropped term, and scaling the measured ratio across the fleet puts the unreported energy at an estimated 8.7–20.2 kWh/m², or 6–13 % of the adopted figure. That range transfers a 60-building ratio onto 8,153 buildings — it sizes the exposure, it does not settle it, and it must not be published as a correction. The honest statement is still that the figure is low, but no longer by an unknown amount.

Four passes running, the defect came from an executor checking its own arithmetic — OPEN-58, OPEN-60, OPEN-61, and now OPEN-62 — and no plan asked for any of those controls. The remedy that keeps suggesting itself is a reconciliation check inside parse_building() rather than in whichever task happens to look.

    Then the replacement check failed — and that is the best thing that happened today. You ruled to replace a check that could never fail with one that could. It could, and it did. Measured against the real geometry code, the measuring script agrees on only 12 of 18 building types, and disagrees on 3,734 buildings. Tracing it showed why: the script was never counting storeys. It counts the number of heights at which a new outside wall begins. On a tower whose glass facade runs unbroken past several floors, that is one height, not several — so a 20-storey building reads as 10. The height fix was right and it was not enough: it corrected an error inside a measurement of the wrong thing. Had the old check been kept, it would have passed again and this would have been signed off as correct today. Nothing built is wrong — the real geometry code reads 20 correctly.
    Then, that evening, you ruled to count floor surfaces instead — and that reader turned out to be half right too. It gets the tower right (20, not 10) and it settled a question nobody had asked: the old method also counts too many, not only too few. A warehouse is a one-storey building whose tall outside wall is built in two stacked bands, and the old reader called that two storeys. So the old column is neither a floor nor a ceiling — the “at least 2.25” wording given that afternoon is withdrawn.
    And the new reader counts attics. A small office is one storey with an attic above it; the attic has a floor, so the reader calls it two. That is 3,580 buildings — 44 % of the fleet. Attics removed, the average storeys built is 2.45, not the 2.94 the run reported, so the figure is published as a range, 2.45 to 2.94, and not as a number. What the item needs now is not a third reader. It needs something this project has never written down: what counts as a storey when a building has an attic, a plenum or a double-height bay. That is a modelling definition, and it is yours to set.
