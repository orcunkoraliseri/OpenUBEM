The main LayoutAssigner arc closed (CP-E signed 2026-07-23) with **4 residual defects deliberately left unfixed** — each was investigated far enough to characterize root cause and scope, then correctly left alone because fixing them was new engineering scope beyond that arc's harvest/reporting charter. #### E-LA-13 — eppy `EpBunch.__repr__` zip-truncation corrupts oversized extensible objects on `idf.save()` → `Outpatient` 100%-Fatal (ROOT CAUSE of E-LA-09) — surfaced 2026-07-23 (T08) — OPEN-BLOCKED
- **Status:** OPEN-BLOCKED, **fully root-caused**. This is the isolated root cause of the closed arc's E-LA-09 (`Outpatient` 100%/6-of-6 Fatal, "root cause not isolated" at plan start). Not a scaling/modeling defect — a third-party (eppy/geomeppy) IDF-serialization bug. `purge_baseline_outputs()` is exonerated; the raw baseline IDF is correct.
- **Signature (EnergyPlus 23.1):** `** Severe ** AirLoopHVAC:OutdoorAirSystem = "AHU-1_OA_EQUIPMENT" invalid Controller List Name="OUTDOORAIR:MIXER" not found.` → `** Fatal ** GetOutsideAirSysInputs: Errors found in getting AirLoopHVAC:OutdoorAirSystem.` (fails at input processing, before sizing/warmup, ~2.6 s). - **Reproduction (decisive, real EnergyPlus 23.1, `-D` design-day):** RAW `ASHRAE901_OutPatientHealthCare_STD2022_Buffalo.idf` → **Completed Successfully, 0 Severe**. The SAME file after a bare eppy load→`IDF.save()` (no scale, no purge, no envelope patch) → **the exact Fatal above**. `scale_baseline_idf`+`purge_baseline_outputs` → same Fatal. `purge_baseline_outputs()` in memory leaves all 4 `AirLoopHVAC:ControllerList` objects intact (its sweep only matches `startswith("OUTPUT")`; 0 OA/HVAC classes match). - **Root cause (isolated to the library):** `eppy/bunch_subclass.py::EpBunch.__repr__` (used by `IDF.save()`→`idfstr()` under the default `standard` outputtype) renders fields via `zip(lines[1:], comments[1:])`, where `comments` is the object's IDD field-name list (`objls`) and `lines` is its stored value list (`obj`). For `Controller:MechanicalVentilation` eppy pre-expands the extensible list to **156** names (= 5 header + 50 zone-groups × 3). `Outpatient`'s two DCV controllers hold **170** (`AHU-1_DCV`, 55 groups) and **194** (`AHU-2_DCV`, 63 groups) values — exceeding 156 — so `zip` truncates to the field-name count, which (a) **silently drops the excess zone-groups** and (b) **drops the `;`-terminated final line**, leaving the object's last written field ending in a **comma**. The object then runs on and absorbs the following object; the second one absorbs the `AHU-1_OA_Controllers` `AirLoopHVAC:ControllerList` (referenced by `AHU-1_OA`), and the resulting field-stream shift makes EnergyPlus parse the EquipmentList as an OutdoorAirSystem → Fatal. Verified in the saved text with `cat -A` (final field ends `,` not `;`) and by eppy source inspection.
- **Blast radius:** exactly **1 of 25** mapped baselines corrupts on `idf.save()` — `Outpatient` only (its 2 MechVent objects). All other 24 baselines save clean, including ones with `Controller:MechanicalVentilation`, because their DCV controllers stay ≤50 zone-groups and never exceed eppy's default expansion. Explains why `Outpatient` is uniquely 100% fleet-wide Fatal and why T03/T05's Midrise/SmallOffice/LargeOffice retests were unaffected.
- **Fix shape (proposed, NOT implemented — STOP-AND-REPORT per T09):** in the `layout_assign` build path, before `self.idf.save()`, extend eppy's extensible IDD for any object whose stored value-count exceeds its field-name count, so `save()` serializes every value and terminates correctly. Must use a **robust** call into eppy's own `increaseIDDfields` (compute the extra-field count and update `objls`/`objidd`/`idd_info` directly) — the naive public trigger `setattr(obj, "<extensible_field_N>", value)` **fails** with `ValueError: '<KEY>' not in list` from `theidf.model.dtls.index(self.key)` (a geomeppy key-casing inconsistency), so it is not a one-liner. Alternative: pin/upgrade eppy to a version whose `__repr__` handles oversized extensible objects. Either touches the shared `idf.save()` path used by every `layout_assign` build and **must be regression-tested across all 25 baselines** before adoption. A terminator-only post-save text patch is rejected: it would stop the Fatal but leave `AHU-1_DCV`/`AHU-2_DCV` silently missing ~5 and ~13 zones from DCV (the dropped zone-groups are lost from eppy's render, not recoverable by fixing the terminator alone).
- **Files touched:** none (investigation only; no code changed — the fix is out of this plan's pre-authorized additive scope and touches shared save-path infrastructure).
