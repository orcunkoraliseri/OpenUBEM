## Executive Summary

The debug-fixes plan (CLOSED, CP-E signed 2026-07-23) fixed 2 of the closed main arc's 4 residual defects (E-LA-10, E-LA-07-class-1) and, along the way, fully **root-caused** 3 more defects but correctly left them **unfixed**, because each requires structural changes to shared infrastructure outside that plan's pre-authorized "additive scaling-tuple" scope. This plan implements those structural fixes, plus one small already-diagnosed geometry gap that risks being unmasked by Phase 1's own fix. In priority/dependency order:

1. **E-LA-12** (small, additive, do first): `Daylighting:ReferencePoint` coordinates are never scaled by `scale_baseline_idf()`. Currently latent/masked (E-LA-07-class-2 fires first, in the same archetypes), but **fixing E-LA-07-class-2 in this same plan risks unmasking it** — fix it first so Phase 1's own retest isn't confounded by a second, different Fatal.
2. **E-LA-07-class-2 / E-LA-08** (highest blast radius — touches every `layout_assign` build, not just failing ones): `envelope_patcher.py`'s `MATERIAL:NOMASS` (zero thermal mass) construction swap causes a `CalcHeatBalanceInsideSurf` warmup divergence in small/marginal zones at non-identity S. **The fix mechanism already exists in the codebase** (`patch_envelope(..., thermal_mass=True)`, confirmed to eliminate the divergence in the debug plan's own T06 evidence) — it is simply never turned on for `layout_assign` today.
3. **E-LA-11** (`LargeOffice` DataCenter WSHP plant-loop runaway): `Coil:*:WaterToAirHeatPump:EquationFit` autosize produces `INF`/`NaN` sizing on shrunk (~2.2 m²) DataCenter zones. No fix exists yet in the codebase; this plan investigates-and-implements against 2 pre-authorized candidate shapes (§5, Phase 2).
4. **E-LA-09 / E-LA-13** (`Outpatient` 100% Fatal): a third-party eppy `IDF.save()` serialization bug (`EpBunch.__repr__`'s `zip()` truncation on oversized `Controller:MechanicalVentilation` objects). The debug plan's T09 evaluated and rejected 2 candidate fixes; this plan proposes and implements a 3rd (§5, Phase 3) not previously attempted.

**Explicitly out of scope for this plan** (per the debug plan's own CP-E disposition, unchanged): **E-LA-14** (`SecondarySchool`-family `CheckWarmupConvergence` Severes, 1.29% fleet-wide) — a Severe-count-only cosmetic regression, `status` stays `success`, already director-accepted as non-blocking. **E-LA-06** — out of scope since the main arc's own Executive Summary, unchanged. Neither is touched by this plan's fixes; both should still be re-measured (not re-investigated) in Phase 4's harvest, same as the debug plan did.

## 3. Dependency decisions (pre-decided, do not re-debate)

1. **Phase order is fixed and dependency-driven, not priority-driven.** T01/T02 (E-LA-12) must run **before** T03/T04 (E-LA-07-class-2 thermal mass), because fixing thermal mass may unmask the daylighting-refpoint Fatal in the same archetypes (`TallBuilding` et al.) — if E-LA-12 is still open when T04 retests, a genuinely-fixed thermal-mass case could look like a failure for the wrong reason. Fixing E-LA-12 first removes that confound.
2. **T03's mechanism is a one-line default change, not new code.** `envelope_patcher.patch_envelope(idf, row, thermal_mass=...)` already implements mass-bearing `MATERIAL` objects (`Density=800.0`, `Specific_Heat=1000.0`, same R-value) when `thermal_mass=True` — see `openubem/geometry/envelope_patcher.py` lines 99-111 — and `BuildingIDF` already threads a `thermal_mass` constructor parameter through to it (`openubem/idf/builder.py` line 459). Neither call site (`run_step3`'s serial path, line 660; `_build_one`'s loky-worker path, line 630) ever passes `thermal_mass=True`, so it defaults to `False` (`MATERIAL:NOMASS`) for every resolution mode today, including `layout_assign`. **Change the constructor's default resolution, not the call sites** (see T03's How) — this keeps the fix contained to one class and preserves external override capability.
3. **T06's primary candidate treats E-LA-11 as a missed-scaling-field problem, same class as E-LA-10/E-LA-07-class-1** — not a novel "clamp geometry" mechanism. Concretely: run the RAW (S=1) `LargeOffice` baseline once through EnergyPlus, read the 4 DataCenter WSHP coils' own autosized `Gross_Rated_Heating_Capacity`/`Gross_Rated_Total_Cooling_Capacity`/`Gross_Rated_Sensible_Cooling_Capacity`/`Rated_Air_Flow_Rate`/`Rated_Water_Flow_Rate` values from the resulting `.eio`, hardcode those literals into a new scaling-spec entry (mirroring `_UNCONDITIONAL_ABSOLUTE_SPECS`'s existing pattern — a baseline-native design value, scaled by S, not a fitted/arbitrary constant), and turn these 5 fields from `autosize` to the resolved-then-scaled literal specifically for the `LargeOffice` DataCenter coils. This is consistent with the "zero-fitted-params" convention this whole scaling engine already follows: the literal comes from EnergyPlus's own reference-scale autosizing run, not from a manager's guess.
4. **T06's fallback (only if the primary candidate fails on real retest) is a `LargeOffice`-scoped minimum-zone-floor-area clamp**, not a fleet-wide one — see T06's "How" for the exact scope guard. Do not generalize this fallback to any other archetype without a separate director decision.
5. **T08's primary candidate is `EpBunch.objls` comment-padding**, not eppy-internal IDD mutation. The debug plan's T09 already tried (and correctly rejected) calling eppy's public extension trigger (`setattr(...)` → `increaseIDDfields` → throws `ValueError` from a geomeppy key-casing bug in `model.dtls.index(self.key)`). This plan's candidate is different and lower-risk: `EpBunch.__repr__` (`eppy/bunch_subclass.py` lines 463-492) truncates via `zip(lines[1:], comments[1:])` where `comments = [c.replace("_", " ") for c in self.objls]` — the truncation is caused by `objls` (the field-name/comment list) being *shorter* than `self.obj` (the real stored values), not by any structural defect in the values themselves. Directly appending placeholder strings to `self.objls` (a plain per-object Python list, comment-only, never parsed by EnergyPlus as anything but a `!-` trailing annotation) until `len(objls) >= len(obj)` fixes the truncation without calling `increaseIDDfields`/`model.dtls` at all. **Do not confuse this with T09's rejected candidate (a)** — that one tried to extend the *real* IDD field registry; this one only pads a cosmetic comment list.
6. **`pytest` for local tests; `sbatch --array` for T11's cluster re-sweep** (same job-array pattern as T17/T18).
